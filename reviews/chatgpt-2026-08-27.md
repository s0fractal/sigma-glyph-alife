### MAJOR — "store holds 26 nodes" не вимірюється

KAPPA-EXP-002 пише:

> at `n=12` the store holds 26 distinct nodes

і далі робить висновок, що content addressing стискає storage нормальної форми до `2n+2`.

А harness робить інше.

`size_dag` — це:

```text
distinct_nodes(normal_form)
```

тобто кількість різних structural hashes, **reachable із поточної in-memory normal form**.

Сам `Store` заповнюється `store_tree()` **до evaluation**, вихідним compiled term. `drive()` під час редукції жодного проміжного чи результатного вузла туди не `put`-ає.

Отже:

```text
distinct hashes in result DAG
≠
objects actually stored in CAS
≠
cumulative objects ever written to CAS
```

Це дуже чистий новий defect class:

> **content-addressable ≠ content-stored**

KAPPA-EXP-006 повторює схожу фразу: "content addressing is Θ(n)… a store never sees the explosion", але його `peak_distinct_hashes` так само рахує максимум distinct hashes **поточного reachable term**, а не cumulative persistent CAS.

Я б не міняв самі measurements. Я б просто розділив три величини:

```text

cas_objects_now
cas_unique_ever_written
```

Кожен окремий experiment у вас чудово preregistered. Але **послідовність**:

```text

→ invented 002
→ result
→ invented 003
→ ...
→ 008
```

є адаптивним пошуком.

І це абсолютно нормально. Це буквально дослідження.

Але "standing statement" після восьми successor experiments — вже не те саме, що preregistered confirmatory result. Ви багато разів адаптивно міняли representation, metric, cost model, family, machine boundary відповідно до попередніх findings. README сам чесно описує цю еволюцію.

```text
ADAPTIVE DERIVATION
```

або

```text
PROGRAM-LEVEL SYNTHESIS
```

Бо `FACT + DERIVATION + HYPOTHESIS` не передають різницю між:

> theorem independently predicted before the programme

і

> theorem shaped through seven rounds of counterexample-guided research.

Це не послаблює результат. Навпаки — робить історію чеснішою.

# `sigma-glyph-alife`: о, а тут уже є м'ясо 😈

## P1 — голодного можна нагодувати, а потім автоматично поховати

Tagline:

> digital agents that run out of food without dying

і вся resumption story каже: `STARVED` зберігає тіло, його можна догодувати.

У runtime:

```text
RUNNABLE = (LIVE, STARVED)
```

Default tick:

```text
phase_reduce()
phase_share()
phase_interact()
phase_cull()
```

`phase_share()` може grant ATP `STARVED`, бо він RUNNABLE.
`phase_interact()` теж може transfer ATP `STARVED`.
Але ні `Economy.grant()`, ні `conservative_transfer()` не переводять статус назад у `LIVE`.

Після цього:

```python
if a.status == STARVED:
    collect(a, a.atp)
    a.status = ARCHIVED
```

Тобто сценарій:

```text
agent STARVED
→ colony gives it enough ATP
→ status still STARVED
→ cull takes ATP back
→ ARCHIVED
```

Прекрасна соціальна програма підтримки 😆

Причому randomized conservation suite цього не ловить: вона перевіряє ledger, bound, dust і determinism, але не семантичну властивість "refed starving agent gets to run".

Мій regression:

```text
starve A
→ transfer enough for next action
→ step(cull=True)
→ ASSERT A is not ARCHIVED
→ ASSERT spent increased or A reached another legitimate state
```

І окремо те саме для rebate.

## MAJOR — знамените `6.41% of the proved ceiling` використовує hindsight

Це дуже гарна знахідка.

ALIFE-EXP-001 задає:

```python
ATP_PER_AGENT = 3000
PER_FAMILY = 16
4 families
```

тобто **64 агенти × 3000 = 192,000 ATP endowment**.

Harness справді створює Economy з:

```python
3000 * len(entries)
```

і дає кожному по 3000.

А RESULT після run бачить:

```text
actual spent = 2776
N = 64
```

і каже:

```text
proved ceiling = 2840
```

тобто:

```text
64 + 2776
```

Після чого:

> 182 distinct addresses = 6.41% of proved ceiling
> operator prepays about sixteen times the memory

Але theorem у Lean має форму:

```text
totalSize ≤ N + budget
provided totalSpent ≤ budget
```

Якщо `budget=2776`, theorem правильний — **після того, як ти вже знаєш, що run витратив 2776**.

Це post-hoc tight bound.

Для справжнього preflight оператор знає максимум 192,000 ATP, який colony може витратити. Тоді theorem дає:

```text
64 + 192000 = 192064
```

Не 2840.

Отже треба розділити:

```text
retrospective bound:
N + actual_spent = 2840

preflight bound:
N + committed/endowed ATP = 192064
```

І тоді фраза про "operator prepays sixteen times" розвалюється набагато сильніше: порівняно з 182 distinct live addresses запас уже не ~16×, а порядку **тисячі разів**.

Це не дефект theorem. Це **неправильне operational reading theorem'а в experiment result**.

І README досі повторює 6.41%.

## MAJOR — population memory theorem не є CAS memory theorem

Lean доводить суму `state.size` агентів.

Runtime після reduction робить:

```python
for a in agents:
    put_term(a.term, store)
```

а CAS старі nodes не видаляє.

Тому знову:

```text
Σ current occurrence size
distinct addresses reachable now
persistent CAS objects accumulated through history
```

— три різні речі.

`population_bound_holds()` перевіряє тільки першу.

А фрази типу "memory bound for population" легко читаються як physical storage bound.

Іронія особливо прекрасна, бо `world/KAPPA-EXP-006` уже витратив цілий experiment, щоб довести, що tree / materialized objects / content hashes / cumulative allocations — різні речі.

Тепер треба перенести цю мудрість назад у ALife:

```text
live_occurrence
live_distinct
cas_resident
cas_unique_ever
python_heap / RSS
```

І тільки перший з них поки що Lean-bound.

## MODERATE — sharing rebate платить агенту за "sharing із самим собою"

Docstring `phase_share` каже:

> rebate agents in proportion to the structure they hold in common with somebody else

А реалізація:

```python
census = population_census(self.agents)
shared = {h for h, n in census.items() if n > 1}
```

`population_census` рахує **occurrences**, включно з кількома occurrences одного hash всередині *одного* агента.

Отже:

```text
Agent A contains hash H twice
Agent B never contains H

global census[H] = 2
→ H classified "shared"
→ A gets sharing rebate
```

Хоча він не ділиться ні з ким.

Якщо desired pressure — **inter-agent commonality**, потрібна інша statistic:

```text
holders[h] = number of distinct agents containing h
shared iff holders[h] >= 2
```

Occurrence multiplicity може бути окремою "self-repetition" ознакою.

Це не security bug. Але це прямий mismatch між policy prose і policy code.
